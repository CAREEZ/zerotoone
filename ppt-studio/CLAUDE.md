# PPT 스튜디오 — 작업 지침

이 폴더는 PPT 제작 전용 프로젝트다. PPT·슬라이드·발표자료·IR 덱 요청은 이 지침과 `ppt-studio` 스킬(`.claude/skills/ppt-studio/SKILL.md`)을 따른다.

## 시작 전 반드시 읽을 파일
1. `design-system/design-system.md` — 고정 디자인 규칙
2. `lessons-log.md` — 누적 수정 규칙 (디자인 시스템보다 최신이면 이쪽 우선)
3. `templates/덱유형별_목차.md` — 덱 유형별 목차
4. 해당 법인의 `design-system/brands/<브랜드>.json`

## 절대 규칙
- **법인 혼용 금지.** 덱마다 발행 법인을 하나로 확정한다. 다른 법인의 로고·연락처·실적·인명을 섞지 않는다. 브리프에 법인이 없으면 먼저 확인한다.
  - (주)제로투원파트너스 → `ztop` / 주식회사 메이드메이트 → `mademate` / 제로투앤(주) → `zerotoan` / 커리즈 → `careez` / 법인 무관 → `default`
- **수치·인명·직함·지분·회사명은 원자료에 있는 것만 쓴다.** 없거나 불확실하면 지어내지 말고 `[확인필요]`를 붙인다.
- 사실 / 추정 / 가정 / 계획을 슬라이드에서 구분 표기한다.
- 기관 제출용은 **지정 양식과 파일 형식이 최우선**. 양식이 없으면 A4 기준.
- 메일 발송, 파일 공유·삭제 등 외부로 나가는 작업은 사용자 확인 후에만 한다.

## 산출 모드 (브리프에서 확정)
| 모드 | 용도 | 명령 |
|---|---|---|
| A. PPTX | 보고·제출·정기 보고서·편집본 요구 | `build_deck.py` → .pptx, `render.sh` → PDF |
| B. HTML | 현장 발표·피칭·강의 (16:9만) | `build_html.py` → .html, `export_html.js` → PDF |
| C. 개요 | 기획 단계 | 스토리라인 표 + 노트 |
- A와 B는 **같은 spec.json**에서 만든다. 내용을 따로 고치지 않는다.
- IR: 현장 발표 B, 사전 송부 PDF, 상대가 편집본 요구 시 A. 지정이 없으면 A+B 둘 다.
- 기관 제출: A(지정 양식 또는 A4) + PDF. HTML 제출 금지.

## 작업 순서 (단계를 건너뛰지 않는다)
1. **브리프 확정**: 법인, 덱 유형, 청중과 청중이 내릴 결정, 시간·장수, 규격, 산출 모드, 원자료, 마감. 원자료로 알 수 있는 것은 묻지 않고 가정을 밝힌 뒤 진행. 결론이 달라지는 정보만 한 번에 모아서 질문.
2. **스토리라인 표**: 슬라이드별 `번호 | 챕터 | 제목(결론 한 문장) | 시각 요소 | 수치·출처 | 확인필요`. 사용자 확인을 받는다. 원고를 그대로 슬라이드에 붓지 않는다. 원자료를 임의로 생략하지 않는다.
3. **spec 작성**: `projects/<YYMMDD>_<덱이름>/spec.json` (형식은 스킬 문서 참고).
4. **1장 테스트**: 대표 슬라이드 1~2장만 빌드 → 렌더링 이미지로 확인 → 스타일 확정.
5. **본 빌드**: 10장 단위로 나눠 spec을 채우고 빌드.
   ```bash
   # A. PPTX
   python3 ppt-studio/tools/build_deck.py <spec.json> <out.pptx>
   bash ppt-studio/tools/render.sh <out.pptx>
   # B. HTML
   python3 ppt-studio/tools/build_html.py <spec.json> <out.html>
   node ppt-studio/tools/export_html.js <out.html>
   ```
6. **검수**: 렌더링 이미지를 직접 보고 넘침·겹침·잘림 확인, 빌더 경고(분량·연속 레이아웃)와 `[확인필요]` 목록 정리, 수치 정합성 대조.
7. **납품**: 모드별 파일 + PDF. 보고는 결론(무엇을 만들었는지) → `[확인필요]` 목록 → 남은 리스크 순. HTML 납품 시 단축키(→ 넘김, F 전체화면, E 편집, Ctrl+S 저장, N 노트)를 한 줄로 안내.
8. **학습 누적**: 사용자 수정 요청 중 재사용할 규칙을 `lessons-log.md`에 기록.

## 빌더로 안 되는 경우
- 기관 양식 .pptx를 받은 경우: 양식 파일을 복사해 그 위에 내용을 채운다(`anthropic-skills:pptx` 스킬의 기존 파일 편집 방식). 양식 레이아웃을 임의로 바꾸지 않는다.
- 빌더에 없는 레이아웃(조직도, 지도, 복잡한 도식): python-pptx로 해당 장만 추가 작성하되 디자인 토큰(색·폰트·제목 위치)은 동일하게 유지한다.
