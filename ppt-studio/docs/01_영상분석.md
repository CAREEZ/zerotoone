## 1. 영상 ② 「오늘, 클로드가 PPT를 죽였습니다.」 (페이퍼로지)

### 1-1. 핵심 주장 (확인된 범위)
1. **AI가 만든 슬라이드는 'AI 티'가 나서 결국 디자이너가 다시 손봐야 한다**는 문제 제기에서 출발. Claude는 이 지점이 다르지만, **세팅 없이 저절로 좋은 결과가 나오지는 않는다**는 입장.
2. **품질은 레퍼런스가 결정한다.** 좋은 PPT를 뽑으려면 좋은 PPT 예시를 먼저 줘야 한다. (후속 블로그)
3. **완성된 글을 그대로 던지지 말 것.** 통째로 넘기면 Claude가 내용을 대충 요약·생략하는 '게으름' 문제가 생긴다. 먼저 슬라이드 단위로 구조화해서 넘긴다. (후속 블로그)
4. **도식화·구조화·수치화가 된 1차본을 먼저 만들고, Claude에게 마무리(디자인)를 맡기는 2단계 방식**이 가장 실패가 적다. 블로그에서는 1차본을 다른 AI 도구로 만든 예시를 듦. (후속 블로그)
5. **결과가 마음에 들면 그 대화창에서 "이걸 스킬로 만들어줘"** → 이후에는 스킬을 선택해 같은 품질을 반복 재현. (후속 블로그)
6. 폰트는 제목용 Paperlogy(채널 운영자가 만든 무료 폰트), 본문용 Pretendard 조합이 함께 언급됨. (관련 스킬 공개 저장소)

### 1-2. 시청자·커뮤니티 반응 (블로그·커뮤니티 후기 기준, 유튜브 댓글 원문 아님)
| 구분 | 반응 | 시사점 |
|---|---|---|
| 긍정 | 영상대로 따라 하니 품질이 꽤 괜찮게 나옴 | 세팅 방식 자체는 재현 가능 |
| 긍정 | HTML로 틀을 잡고 PPTX로 변환하므로 PowerPoint에서 텍스트·배경 편집 가능 | **편집 가능한 산출물**이 실무 핵심 가치 |
| 부정 | Pro 요금제에서 10~20장 만에 사용 한도 도달, 상위 요금제도 100장에 주간 한도 61% 소진 사례 | 한 번에 다 만들지 말고 **분할 생성**, 1장 테스트로 낭비 차단 |
| 부정 | 10장이 넘어가면 생성 중 멈춤(뻗음), 30장 일괄 생성 실패 | **10장 이하 배치**로 나눠 생성 |
| 부정 | 차트가 네이티브 차트가 아니라 도형으로 그려짐 | 프롬프트에 **"네이티브 차트(데이터 편집 가능)"를 명시** |
| 부정 | 공식 pptx 스킬 기본 결과가 기본 테마보다 못하다는 평 | 기본 스킬만으로는 부족 → **자체 디자인 시스템 필수** |
| 중립 | 제목·썸네일이 자극적('죽였다')이라는 평 | 완전 자동화 기대는 금물. 초안 80% + 사람 검수 20% |

### 1-3. 같은 영상을 참고한 실무자들이 정리한 세팅 절차 (공통분모)
1. **디자인 시스템 확보**: 좋아하는 브랜드 스타일을 디자인 규칙 문서로 가져옴(getdesign.md 등 브랜드 디자인 시스템 모음 활용 사례).
2. **내 용도로 커스터마이즈**: 폰트(Pretendard 고정), 로고, 비율(16:9), 챕터명·제목 위치를 매 페이지 동일하게.
3. **1장 테스트 → 미세 조정 반복**: 피드백은 말보다 파일(수정한 슬라이드, 캡처)로 주는 게 정확.
4. **확정된 지침을 Claude 프로젝트 지침에 고정**, 로고·양식·레퍼런스는 지식 파일로 업로드.
5. **고급**: 스킬로 저장하고, 수정할 때마다 수정 기록을 스킬 파일에 누적 → 쓸수록 결과가 좋아짐.

부가 팁: 한 슬라이드에 핵심 메시지 1개, 불릿 3개 이내, 복잡한 데이터는 표로.
