## 1. 영상 ① 에이커 — HTML + 모션그래픽 슬라이드

### 핵심 주장
| 주장 | 평가 | 이 프로젝트의 처리 |
|---|---|---|
| AI는 바이너리인 PPTX보다 텍스트 코드인 HTML/CSS를 더 잘 만든다 | **타당함.** 다른 실무 글도 같은 주장(HTML/CSS 학습 데이터가 python-pptx보다 압도적으로 많음) | HTML 모드 추가 |
| 웹폰트(Google Fonts)를 불러오면 어떤 PC에서도 폰트가 깨지지 않는다 | **부정확함.** 발표장 PC가 오프라인이거나 사내망·보안망이면 Google Fonts가 로드되지 않아 기본 글꼴로 바뀜 | **Pretendard를 HTML 안에 내장**(base64). 인터넷 없이도 동일하게 렌더링 |
| `contenteditable`로 발표 화면에서 바로 수정한다 | **절반만 맞음.** 브라우저에서 고친 내용은 저장하지 않으면 새로고침할 때 사라짐. 발표 중 실수로 클릭하면 편집될 위험도 있음 | **편집 모드를 따로 켜고 끔(E)** + **저장(Ctrl+S → `_edited.html`)**. 저장 후 다시 열어 유지되는 것까지 테스트함 |
| SVG·CSS 애니메이션으로 가볍고 세련된 모션 | 타당함. 단 과한 모션은 집중을 깨뜨림 | 모션은 **등장 1회**만 씀(요소 순차 등장, 막대 성장, 선 그리기, 숫자 카운트업). 장식 모션 금지. 동작 줄이기 설정을 켠 PC에서는 모션 꺼짐 |
| 최종 원본 .pptx 납품이 필요한 환경에서는 대응 전략이 필요 | 타당함. 투자사·기관은 파일 제출을 요구함. HTML 첨부는 메일 보안 필터에 걸리기도 함(일반적 리스크) | **같은 spec에서 PPTX·PDF도 생성.** 송부·제출은 PDF/PPTX로 |

## 2. 영상 ② 페이퍼로지 — 디자인 시스템 기반 Claude PPT 자동화

### 핵심 주장
| 주장 | 근거 | 이 프로젝트의 처리 |
|---|---|---|
| 'AI 슬롭'(성의 없는 저품질 AI 결과물)은 디자인 시스템을 고정해서 막는다 | 사용자 분석 + 2차 자료 일치 | `design-system/` + 프로젝트 지침에 고정 |
| 해외 기업 디자인 가이드(getdesign.md 등)를 차용하되 16:9·Pretendard·3~4색으로 커스터마이즈 | 사용자 분석 + 2차 자료 일치 | 브랜드 토큰 JSON, 60-30-10 색 비율 |
| 레이아웃·여백·글자 크기 규칙은 영어로 쓰면 더 엄격히 지켜진다 | 실무 사례 수준. 확증된 사실은 아님 | 비용이 거의 없어 채택함. **디자인 규칙 블록만 영어**, 내용·사실 규칙은 한국어 |
| 처음부터 10~20장을 만들지 말고 1장 대표 슬라이드로 피드백 루프 | 사용자 분석 + 2차 자료 일치 | 작업 순서 3단계(1장 테스트) |
| 엑셀이 연동되는 네이티브 차트로 수치 수정을 쉽게 | 사용자 분석 + 후기의 '도형 차트' 불만 | `build_deck.py`로 네이티브 차트 생성 |
| 노션 메모·워드·기존 PPT를 넣으면 디자인 시스템으로 재구성 | 사용자 분석 | 리디자인 프롬프트 |
| 한도·분량 문제: 10장이 넘으면 생성이 멈추거나 사용 한도에 도달 | 2차 후기 | 10장 단위 분할 생성 |

## 3. 시청자 반응에서 뽑은 실무 포인트 (경향만 반영)
1. **텍스트 밀도가 품질을 결정함.** AI는 줄글을 길게 씀 → 지침으로 강제(불릿 4개, `키워드: 짧은 구`, 문단 금지).
2. **기획과 핵심 메시지는 사람, 디자인과 배치는 AI.** → 스토리라인 표는 반드시 사람이 확인.
3. **툴 종속(Gamma 등)보다 내 디자인 시스템이 낫다.** → 브랜드 룩앤필 고정.
4. **발표장 폰트 깨짐이 가장 큰 고통.** → 폰트 내장 HTML + PDF.
5. **장수는 먼저 정해 준다.** AI에 맡기면 한 장에 욱여넣음 → 브리프에서 장수 지정.

## 4. 통합 워크플로우 (이 프로젝트에 구현됨)
```
[1] 브리프: 법인·청중·결정사항·장수·규격·산출 모드
[2] 스토리라인 표 (사람이 확정) ── 한 장 = 메시지 1개 = 시각 요소 1개
[3] spec.json 작성 ─┬─ 1장 테스트 → 스타일 확정
                   │
[4] 산출 모드 ──────┼─ A. PPTX (보고·제출·정기 보고서) : build_deck.py → .pptx + PDF
                   ├─ B. HTML (발표·피칭·강의)      : build_html.py → .html(폰트 내장) + PDF
                   └─ C. 개요·스크립트만             : 스토리라인 표 + 발표자 노트
[5] 검수: 렌더링 이미지 육안 확인, [확인필요]·분량 경고, 수치 정합성, 법인 혼용
[6] lessons-log.md에 수정 규칙 누적
```
- A와 B는 **같은 spec**에서 나오므로 내용이 어긋나지 않음.
- IR은 **현장 발표 = HTML, 사전 송부 = PDF, 상대가 편집본 요구 = PPTX**로 나눠 씀.

## 5. 사용자 제공 지침에서 고친 부분
| 원래 내용 | 수정 | 이유 |
|---|---|---|
| Google Fonts 호출 | 폰트 내장 | 오프라인 발표장 대응 |
| 모든 텍스트에 `contenteditable` 상시 적용 | 편집 모드 토글 + 저장 | 발표 중 오입력 방지, 수정본 보존 |
| Mode B: python-pptx **코드를 사용자에게 제공** | Claude가 **파일을 직접 생성** | 사용자가 코드를 실행할 필요 없음 |
| 정기 보고서는 "일반 채팅창"에서 요청 | 프로젝트 안에서 요청 | 프로젝트 밖에서는 지침이 적용되지 않음 |
| 지침에 법인·사실 관리 규칙 없음 | 법인 구분, `[확인필요]`, 기관 양식 우선 추가 | 사용자 업무 기준 |
| 불릿 최대 8단어(영어 기준) | 한국어 기준 불릿 4개, 각 40자 이내(권장 25자) | 한국어 분량 환산 |
