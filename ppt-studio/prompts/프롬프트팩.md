# 프롬프트 팩 — 단계별 복사해서 쓰기

원칙: **한 번에 "PPT 만들어줘" 금지.** 브리프 → 스토리라인 → 1장 테스트 → 10장 단위 생성 → 검수 순서로 간다. `{ }` 부분만 바꿔 쓴다.

---

## 0단계. 브리프 (매 덱 시작 시)
```
PPT 작업 시작. 아래 브리프로 진행해.

- 발행 법인: {(주)제로투원파트너스 / 주식회사 메이드메이트 / 제로투앤(주) / 커리즈 / 법인 표기 없음}
- 덱 유형: {IR / 정부사업 발표평가 / 강의 / 투심 보고 / 제안서 / 내부 보고}
- 청중과 그들이 내려야 할 결정: {예: 투자심사역 — 후속 미팅 여부}
- 발표 시간·장수: {예: 10분, 본문 12장} ← 장수는 반드시 지정 (AI에 맡기면 한 장에 욱여넣음)
- 규격: {16:9 / A4 가로 / A4 세로 / 기관 양식 첨부}
- 산출 모드: {A. PPTX(보고·제출) / B. HTML(현장 발표·피칭) / A+B / C. 개요만}
- 원자료: {첨부 파일명}
- 마감: {날짜}

먼저 원자료를 읽고 ① 핵심 메시지 3개 ② 빠진 정보·확인 필요한 수치 목록만 답해. 슬라이드는 아직 만들지 마.
```

## 1단계. 스토리라인 (원고를 통째로 슬라이드로 바꾸지 않는다)
```
원자료를 슬라이드별 표로 구조화해.
열: 번호 | 챕터 | 제목(결론 한 문장, 40자 이내) | 레이아웃(kpi/chart/table/compare/process/bullets) | 들어갈 수치와 출처 | 확인필요

규칙:
- 한 장에 메시지 1개, 주인공 시각 요소 1개(3초 안에 요지 파악). 제목만 이어 읽어도 전체 논리가 서야 함.
- 같은 레이아웃을 연속으로 배치하지 마.
- 불릿은 '키워드: 짧은 구' 형식, 장당 4개 이내.
- 원자료에 없는 수치는 만들지 말고 [확인필요]로 표시.
- 원자료 내용을 생략·요약해서 빠뜨리지 마. 분량이 넘치면 부록으로 보내고 표에 '부록'이라고 적어.
```
→ 표를 검토·수정한 뒤 다음 단계로.

## 2단계. 1장 테스트 (디자인 확정)
```
스토리라인 {3}번 슬라이드 1장만 디자인 시스템대로 만들어.
- ppt-studio 디자인 시스템(Pretendard, 16:9, 제목 위치 고정, 강조색 1곳) 적용
- 차트는 네이티브 차트로
- 결과를 이미지로 렌더링해서 보여주고, 디자인 시스템 위반 사항을 스스로 점검해서 같이 보고해.
```
피드백은 말보다 파일이 정확함: 마음에 드는 레퍼런스 슬라이드 캡처, 직접 고친 슬라이드를 첨부.

## 3단계. 본 생성 (10장 단위)
```
확정된 1장 스타일로 {1~10}번 슬라이드를 만들어.
- 10장 넘으면 나눠서 진행. 이번 배치는 {1~10}번만.
- 각 장 발표자 노트에 30~60초 분량 스크립트 작성.
- 끝나면 [확인필요] 목록과 분량 경고를 정리해서 보고.
```

## 4단계. 검수·수정
```
완성본을 아래 기준으로 검수하고 문제 있는 장만 고쳐.
1) 제목만 이어 읽을 때 논리가 이어지는가
2) 수치가 원자료·다른 장과 일치하는가 (같은 숫자 다른 표기 포함)
3) 디자인 시스템 위반(폰트, 강조색 2곳 이상, 12pt 미만, 넘침·겹침)
4) 발행 법인·로고·연락처 혼용 여부
5) [확인필요] 잔존 항목
결과는 '장 번호 | 문제 | 조치' 표로.
```

## 5단계. 학습 누적 (덱 완료 후)
```
이번 작업에서 내가 수정 요청한 사항 중 다음 덱에도 적용할 규칙만 골라
ppt-studio/lessons-log.md 형식으로 추가해. 일회성 수정은 제외.
```

## 보조 프롬프트

### HTML 발표본 만들기 (확정된 PPTX 원고 기준)
```
확정된 스토리라인(또는 spec)으로 HTML 발표본을 만들어. 내용은 PPTX와 한 글자도 다르지 않게.
- 단일 .html, 1280x720, Pretendard 내장(외부 폰트 호출 금지)
- 모션은 등장 시 1회: 순차 등장, 막대 성장, 선 그리기, 숫자 카운트업
- E 편집 모드 / Ctrl+S 저장 / F 전체화면 / N 노트 / 인쇄 시 장당 1페이지
- 발표장 PC에서 열어 볼 체크리스트도 같이 줘.
```
발표장 체크: ① 인터넷을 끈 상태로 열어 폰트 확인 ② F 전체화면 ③ 클릭리모컨(PageDown) 동작 ④ 예비로 PDF를 USB에.

### 발표 직전 오탈자 수정 (HTML)
브라우저에서 `E` → 글자 수정 → `Esc` → `Ctrl+S`(`_edited.html` 저장). 원본 spec에도 같은 수정을 반영해 달라고 요청한다(안 하면 다음 빌드에서 수정이 사라짐).

### 수치만 바뀌는 정기 보고서 (PPTX)
```
지난달 spec을 복사해 아래 수치만 바꿔 다시 빌드해. 문구·레이아웃은 바꾸지 마.
바뀐 수치 목록: {표 붙여넣기}
전월 대비 차이가 큰 항목(±20% 이상)은 제목 문구도 맞는지 점검해.
```
PowerPoint에서 직접 고칠 때는 차트 더블클릭 → 데이터 편집(엑셀)으로 숫자만 바꾼다.

### 레퍼런스 덱에서 디자인 규칙 추출
```
첨부한 레퍼런스 PPT(또는 캡처)의 디자인 규칙을 추출해.
색(HEX), 글꼴 위계(pt), 여백, 제목 위치, 차트 스타일, 반복 레이아웃 패턴.
ppt-studio/design-system/brands/{브랜드}.json 형식으로 제안하되, 바로 덮어쓰지 말고 차이점을 먼저 보여줘.
```

### 기존 PPT 리디자인
```
첨부 PPT의 내용은 그대로 두고 디자인만 ppt-studio 디자인 시스템으로 다시 만들어.
- 내용 삭제·요약 금지. 넘치면 장을 나눠.
- 그림으로 된 차트는 원본 수치를 뽑아 네이티브 차트로 다시 그려. 수치를 못 읽으면 [확인필요].
```

### 기관 양식 맞추기
```
첨부한 기관 양식(.pptx/.hwp/.pdf)의 목차·필수 항목·분량 제한을 먼저 표로 정리해.
그다음 스토리라인을 양식 항목에 1:1로 매핑해. 양식에 없는 장은 만들지 마.
```

### 결과물이 마음에 들 때 (스킬화)
```
지금 이 결과물의 스타일과 작업 방식을 ppt-studio 스킬/디자인 시스템에 반영해.
바뀐 규칙만 요약해서 보여주고, lessons-log.md에도 기록해.
```
